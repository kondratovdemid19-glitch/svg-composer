# Сборка

Редактор векторных композиций из готовых SVG-компонентов. Загружается библиотека, по заголовку или названиям подбираются исходные объекты, затем композицию можно отредактировать и скачать как SVG.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
npm ci
npm run dev
```

Откройте адрес, который покажет Vite. Для проверки и сборки:

```sh
npm test
npm run build
```

Собранный `dist` размещается на обычном статическом хостинге. Сервер, ключи и платные сервисы не нужны.

## Как пользоваться

1. Загрузите SVG-компоненты с понятными названиями: например, `Кошелек.svg`, `Монета.svg`, `Лампа.svg`. Можно выбрать несколько файлов сразу или перетащить их в рабочую область.
2. В режиме «По смыслу» введите заголовок. В режиме «По объектам» перечислите нужные компоненты. Нажмите «Собрать».
3. Любой объект можно добавить непосредственно из библиотеки. На холсте — перетаскивание; справа — координаты, равномерный масштаб, поворот, дублирование и удаление. Стрелки перемещают выбранный объект на 1 пиксель, Shift + стрелка — на 10. Ctrl/Cmd + Z отменяет изменения сцены, Shift + Ctrl/Cmd + Z возвращает их.
4. В списке слоёв можно выбрать, скрыть, заблокировать объект и поменять порядок наложения.
5. Выберите палитру, измените цвета вручную или загрузите TXT со списком HEX-цветов / JSON-массив из 2–8 разных цветов. Нажмите «Применить». Исходные цвета можно вернуть.
6. «Экспорт SVG» сохраняет редактируемые векторные группы. «Сохранить проект» сохраняет также исходники, теги, видимость и блокировку слоёв. Этот JSON можно открыть на другом устройстве.

## Как устроено

- **Импорт.** SVG разбирается как XML и проверяется по разрешённым элементам и атрибутам. Скрипты, внешние ссылки, растровые изображения и неподдерживаемые конструкции отклоняются с объяснением. Ничего не удаляется молча. Допускаются пути, примитивы, группы, градиенты, маски, внутренние ссылки и поддерживаемые фильтры. Текст в исходнике нужно предварительно перевести в кривые.
- **Хранение.** В проекте сохраняются исходный текст файла, его SHA-256, проверенный SVG, размер, название и теги. SHA-256 позволяет обнаруживать одинаковые файлы; это не цифровая подпись владельца. Автосохранение работает локально через IndexedDB. Файлы не отправляются на сервер.
- **Извлечение.** Объектом библиотеки является отдельный исходный SVG-компонент. После экспорта группы из редактора иллюстраций её нужно загрузить один раз; дальше приложение получает компонент из библиотеки по стабильному идентификатору. Автоматического разрезания цельной иллюстрации на смысловые части здесь нет.
- **Подбор.** Используется открытый небольшой словарь предметов и тем плюс названия и редактируемые теги. Режим «По смыслу» сопоставляет темы, режим «По объектам» — предметы. Это детерминированный поиск, без вызова LLM и без распознавания картинки. Ненайденный запрос не заменяет текущую композицию. Неизвестные предметы можно добавить вручную и снабдить тегами.
- **Композиция.** Для найденных компонентов рассчитываются ячейки и единый масштаб по двум ограничениям. Пропорции остаются исходными. Сцена хранит ссылки на компоненты и преобразования, а не изменённые контуры.
- **Переиспользование и экспорт.** Каждый экземпляр получает собственные идентификаторы градиентов, масок и внутренних ссылок. Один исходник можно дублировать без конфликтов. Пути и геометрические атрибуты сохраняются. Меняются только преобразования группы и выбранные цвета. SVG собирается заново из проверенной сцены, поэтому рамка выделения и другие элементы интерфейса в результат не попадают.

## Ограничения

- До 100 исходников, до 3 МиБ на SVG, общий объём библиотеки до 25 МБ; на холсте до 50 экземпляров. Автоматический подбор выбирает до пяти компонентов. Размер холста — 100–4096 пикселей; в интерфейсе доступны четыре формата.
- Сложные метафоры вне словаря не интерпретируются автоматически. Следующий шаг — отдельный необязательный LLM-планировщик, возвращающий только существующие идентификаторы компонентов; преобразование геометрии моделью не требуется.
- Назначение объекта ограничивает доступные группы палитры; внутри группы цвета сопоставляются по порядку. Почти чёрные контуры сохраняются. Некоторые нестандартные SVG-возможности намеренно не поддерживаются.
- JSON проекта содержит полные исходники. Закрытую библиотеку и композиции из неё нужно передавать только её владельцу, если отдельного разрешения на публикацию нет.

## Проверка и статус задания

Тесты проверяют сохранение геометрии и внутренних ссылок, безопасный импорт, подбор, пропорции, палитры, преобразования, дублирование, скрытые и заблокированные слои, отмену и перенос проекта. Тестовые фигуры написаны вручную и не выдаются за библиотеку работодателя.

Проверены все 40 оригинальных компонентов: 10 основных и 10 фоновых объектов в каждом из размеров S/L. Подготовлены три редактируемые композиции в трёх исходных цветовых схемах. Исходники и примеры передаются автору задания отдельно; в публичном репозитории их нет. Контрольные суммы исходников, неизменность контуров, переход L→S и воспроизводимость экспорта проверены отдельно. 71 автоматическая проверка и сборка прошли.

## AI-инструменты

Codex использовался для разработки, тестов и ревью. Отдельная проверка кода проведена помощником с изолированным контекстом. Новые иллюстрации с помощью AI не создавались. В работающем приложении нет скрытых запросов к моделям; способ подбора явно указан в интерфейсе.

## Детализация и правила исходной библиотеки

S/L — это два предоставленных исходника с разной детализацией, отдельно от размера холста. Имена `Кошелек--S--main.svg`, `Кошелек--L--main.svg` автоматически задают общее семейство, детализацию и назначение. Для фона используется `background`, например `Облако--S--background.svg`. Обычные имена получают выбранную при загрузке детализацию и назначение «Основной объект».

Библиотека и подбор используют выбранную детализацию. Переключение готовой сцены требует ровно одного исходника нужного размера с тем же семейством и назначением для каждого слоя. Новый вариант равномерно вписывается в прежнюю рамку, положение, поворот, порядок и видимость сохраняются. Если пары нет или она неоднозначна, вся операция отменяется. Недостающие детали не генерируются.

Семейство, назначение и S/L редактируются справа через кнопку «Свойства» или список всех исходников над библиотекой. Список включает также скрытые другой детализацией компоненты. Нельзя изменить детализацию используемого слоя отдельно от сцены. Метаданные не меняют исходные байты, подпись или геометрию. Идентичные по байтам SVG считаются одним исходником: назначить им две отдельные роли или детализации одновременно нельзя.

В трёх исходных схемах две отдельные группы: «Цвета объектов» и «Цвета фона». Основные объекты могут использовать обе группы; фон — только фоновую. Цвета библиотеки сопоставляются по общим цветовым позициям; сиреневая схема сохраняет исходные цвета, белая бумага остаётся белой во встроенных схемах. Для сторонних цветов используется общая таблица в пределах назначения. Тёмные контуры, прозрачность и служебные цвета масок/фильтров сохраняются. Поля цветов меняют выбранную схему; «Применить» сохраняет её в сцене, «Исходные цвета» отменяет обе группы.

TXT или JSON-массив из 2–8 HEX-цветов задаёт цвета объектов, а фон сбрасывает на нейтральный `#e4e9f1`. Для обеих групп загрузите JSON:

```json
{"background":["#eeeeee"],"objects":["#7165b7","#f2c879"]}
```

В каждой группе допустимо 1–8 разных HEX-цветов. Применённые группы сохраняются в проекте. Старые проекты без метаданных получают L/основной объект и семейство из имени; старая таблица замены цветов применяется только к основным объектам, фон сохраняет исходные цвета. Неверные значения метаданных и палитр отклоняются.

Правила проверены на контрольных фигурах и оригинальных компонентах. Три итоговых макета дополнительно отредактированы вручную: они показывают редактирование и переиспользование. Подбор по смыслу и по объектам проверен отдельно в браузере. Подбор выбирает до пяти семейств, предпочитая основную версию фоновой копии. Фон можно добавить вручную; семейства только с фоновым исходником также доступны подбору.
